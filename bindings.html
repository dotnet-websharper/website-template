Bindings

Typed bindings for the JavaScript ecosystem

Hand-written, strongly typed F# and C# wrappers for the libraries and browser APIs you already use. Each package targets a specific upstream version, so the types match the JavaScript you actually ship.

28 JavaScript libraries 41 browser APIs

Binding versions are refreshed from NuGet. Library versions show the latest stable release on npm.

Why typed bindings

Declare a JavaScript API once, use it as typed code everywhere

The WebSharper Interface Generator (WIG) turns a JavaScript API into a typed, machine-readable definition. From that single definition WebSharper generates idiomatic F# and C# — plus the interop glue — so you call JavaScript with the same confidence as native code.

one WIG definition → F# types C# types JS interop

  • Type-safe across the boundary

    Every method, option and return type is checked by the F# or C# compiler. A renamed function, a missing required option or the wrong argument is a build error — not a runtime crash.

  • Machine-readable and AI-friendly

    A WIG definition is structured metadata, not prose. Tools and AI agents can read it to generate complete, consistent bindings — and to pinpoint exactly what changed when the upstream API moves.

  • Pinned to the library you ship

    Each binding records the upstream release it targets, so its types match the JavaScript you actually load. The freshness badge on every card shows when you are current — or behind.

  • No hand-written interop

    No obj, no dynamic, no stringly-typed escape hatches and no manual marshalling — generated bindings compile straight down to the underlying JavaScript calls.
