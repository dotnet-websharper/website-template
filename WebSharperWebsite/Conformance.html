Known differences

WebSharper implements a .NET API in JavaScript when it can follow .NET semantics exactly or very closely. It doesn't when that would bloat small, readable output just for coverage, or when only a partial imitation is possible, such as System.Type, which cannot tell apart .NET types that share a JavaScript representation. Those cases are listed here, each with the ${Lang} or JavaScript API to use instead.

How this is computed

The cases live in WebSharper's own repository (${Project}). The same ${Lang} project is built for .NET and with WebSharper, run on .NET and under Node, and the outputs are compared. The check runs on every release build against a committed baseline, so a change that makes any case worse fails the build.${TsNote}
