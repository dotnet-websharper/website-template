Included · 01 dotnet ws, the WebSharper CLI

Builds that keep pace with your thinking.

Every dotnet build evaluates MSBuild again and starts a cold compiler. On a full-stack WebSharper solution that adds up to minutes a day, for every developer. dotnet ws hands compilation to the Booster, the WebSharper compiler that stays warm between builds. It remembers your solution's project graph, rebuilds each project in dependency order, and falls back to a full build on its own when the structure changes.

Always warm
A long-running compiler, not a cold start on every build.
Graph-aware
Whole solutions, references first, from a cached project graph.
Never wrong
Structural change? It falls back to a full build automatically.
~/src/shop · zsh Booster warm

$ dotnet ws build

✓ Shop.Server boosted

✓ Shop.Client boosted

One tool for the whole inner loop

dotnet ws build

Boosted builds

A project or a whole solution through the warm compiler, in the right order. Add --time to see where every millisecond goes.

dotnet ws watch

Edit, save, done

Watches your folder and rebuilds the projects, or recompiles the files, that changed. Narrow it with a glob and stay in flow.

dotnet ws compile

One file to JS or TS

Turn a single .fs or .fsx into JavaScript or TypeScript against any WebSharper version, with no project to set up. Perfect for spikes, snippets and shared modules.

dotnet ws mcp

The bridge to your agent

Connects any MCP client to the Booster that matches your project's WebSharper version, and picks up extensions such as Booster Pro on its own.

The same fast path on every machine.

Pin dotnet ws in your repository's tool manifest and every developer, and every CI agent, builds the same way. The only prerequisite is the .NET SDK: WebSharper packages and the Booster arrive with the projects that use them.

  • Runs on .NET 8 through 11, no extra runtime needed
  • Finds the nearest project or solution on its own
  • Several WebSharper versions side by side
  • list, start and stop keep the Booster under control
Open source under Apache 2.0. dotnet-ws on NuGet → Source on GitHub →

Faster by your next build

  1. 1

    Add it to your repository's tool manifest.

    dotnet tool install dotnet-ws

  2. 2

    Build through the Booster.

    dotnet ws build

  3. 3

    Leave dotnet ws watch running and forget about builds.

Included · 02 WebSharper Booster Pro

Your AI agent, fluent in WebSharper from the first prompt.

General-purpose agents guess. They search the web, land on superseded 4.x docs, decompile references and burn full builds to discover what the compiler already knew. Booster Pro plugs Claude Code, Copilot, Cursor or any MCP client straight into the WebSharper booster: the process that just compiled your project and holds its type check, its JavaScript translation and every referenced library in memory.

No guessing

Four tools your agent will reach for constantly

get_guide

Guides that compile

Concise how-tos for remoting, reactive UI, templating, sitelets, JS interop and diagnostics, written against this release. Ask for WS9002 or ListModel and get the right section, even before the first build.

get_source

Library source on tap

The real F# source of any type, module or member, from your project or any referenced WebSharper library. Your agent reads how it works instead of inventing how it might.

find_examples

Proven usage, instantly

Working code that uses a given API, pulled from your codebase and from the sources of the libraries you reference. New code follows patterns that already ship.

get_generated_js

See the JavaScript

The exact JavaScript WebSharper emitted for a type or member, from your last build or a library's sidecar. Debug client behaviour and bundle size with facts.
