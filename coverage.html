How this is computed

Nothing here is maintained by hand. The compiler's own metadata for WebSharper.StdLib lists every member it can translate and how: an inline JavaScript template, a compiled proxy, or a macro. Each public constructor and method of the .NET reference assemblies and FSharp.Core is matched against it by exact signature, so overloads are reported separately.

Translates: a JavaScript translation exists for this exact signature.
Maybe: no member entry, but the type is handled by a macro that may cover it.
Not translated: using it from client code is a compile error (WS9001). Use it on the server, or call a JavaScript API instead.

Primitive operators (a + b on numbers), F# records, unions and pattern matching, and other language constructs are compiled directly and are not listed as members. Attributes are compile-time only and are left out.

For tools and AI agents

The same data is published as JSON, so an agent can check a member before writing client code that uses it.

  • /Assets/coverage/index.json : every namespace and type, with counts
  • /Assets/coverage/<library>/<namespace>.json : the members, e.g. dotnet/System.Collections.Generic.json

Each member has a status (covered, maybe, missing) and a via telling how it is translated. Namespaces without a file have no translated members.

Whether translated code also gives the same results as on .NET is checked separately: see C# conformance and F# conformance.
